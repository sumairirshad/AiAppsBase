# YouTube Content Planner (MVP)

A minimal web app replacing a YouTube content-planning Excel sheet. Lets you
add, view, and edit planning entries (title, status, date, notes) across
8 categories: Channel Profile, Playlists, Podcasts, Shorts, Videos,
Community Posts, Posting Concept, and Live Broadcast.

UI built with shadcn/ui (base-nova style, Base UI primitives) in a
YouTube-red/white theme. Forms use react-hook-form + zod for validation,
with shadcn's Field components for layout/error display, and Sonner for
toast feedback.

## Setup

```bash
cd youtube-manager
npm install
npm run dev
```

Open http://localhost:3000.

## Data mode

Controlled by `USE_MOCK_DATA` in `.env.local`:

- `USE_MOCK_DATA=true` — everything simulates success against in-memory
  mock data (`lib/mockData.js`), reset on server restart. No network calls
  are made. Good for testing the UI.
- `USE_MOCK_DATA=false` — real mode. Before any real call, the required
  env vars are validated (`lib/env.js`); if anything is missing or
  malformed, the add/edit form shows a clear error (toast + inline) naming
  exactly what's wrong, instead of failing silently.

Not every category maps to a real YouTube endpoint — see
`lib/categories.js`'s `realCapability` field:

| Category | In real mode |
|---|---|
| Playlists | Real playlist created/updated via the YouTube Data API (OAuth) |
| Live Broadcast | Real scheduled broadcast created/updated via the YouTube Data API (OAuth) |
| Channel Profile | Real channel branding (title/description) updated via the YouTube Data API (OAuth); the page also shows live channel stats (read-only, API key) |
| Videos, Shorts | Real video upload via the YouTube Data API (OAuth) — the add form requires a video file in real mode. Shorts and Videos use the same upload call; YouTube has no separate "Short" endpoint |
| Podcasts, Community Posts, Posting Concept | Always stored in the local JSON file (`data/db.json`), in both modes — YouTube has no public API for these |

Everything real-mode creates defaults to **private** visibility on YouTube,
so nothing goes live on your channel by accident from this planning tool.

All pages and API routes go through `lib/dataService.js`, which checks
`USE_MOCK_DATA` and routes to mock data, the local JSON store, or the real
YouTube API calls in `lib/youtubeApi.js` as appropriate.

### Real API env vars

See `.env.example` for the full list: `YOUTUBE_API_KEY`,
`YOUTUBE_CHANNEL_ID`, `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`,
`YOUTUBE_REFRESH_TOKEN`. The last one is generated by running:

```bash
node scripts/get-youtube-token.mjs
```

This is a one-time local OAuth consent flow — it prints a URL to open in
your browser, then prints the refresh token to paste into `.env.local`.

**Note:** the real-mode YouTube API calls are written against the
documented API shapes but haven't been exercised against a real Google
Cloud project in this environment (no real credentials available here) —
verify end-to-end against your own channel before relying on it.

## Structure

- `app/page.js` — dashboard listing the 8 categories
- `app/[category]/page.js` + `add-entry-form.jsx` — list + add-entry form
- `app/[category]/[id]/page.js` + `edit-entry-form.jsx` — edit-entry form
- `app/api/entries/[category]/route.js` — create (POST), handles file upload
- `app/api/entries/[category]/[id]/route.js` — update (PATCH)
- `components/app-sidebar.jsx` — category navigation
- `lib/categories.js` — the 8 categories, status options, real capabilities
- `lib/validation.js` — shared zod schema (client + server validation)
- `lib/dataService.js` — mock/real switch + YouTube write orchestration
- `lib/mockData.js` — in-memory mock store
- `lib/realData.js` — local JSON file store (`data/db.json`)
- `lib/env.js` — real-mode env var validation
- `lib/googleAuth.js`, `lib/youtubeApi.js` — OAuth client + real API calls
- `scripts/get-youtube-token.mjs` — one-time OAuth consent script
